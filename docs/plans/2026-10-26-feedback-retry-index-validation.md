# 评价重试索引与大目录验证

## 问题与实现

对应 [PR #635 的重试延迟评审](https://github.com/soimy/openclaw-channel-dingtalk/pull/635#discussion_r4373732606)，基线提交为 `b88bf4922a2211a7cd0a936e677445504706f9b0`。原实现释放就绪队列位置后，到期依赖重新扫描状态目录；每个目录项默认等待 100ms，历史量会叠加到普通重试延迟中。

本次保留 128 项就绪队列，新增最多 1024 项的重试索引。索引只保存账号引用、卡片标识、到期时间、失败次数和调度标记，不保存问答正文；满载时优先保留较早到期的任务。已索引任务到期直接定位小文件，每次调度最多接纳一项，不等待目录遍历。新评价可提前唤醒对应记录，执行时仍读取最新评价及回执。

receipt 仍负责持久化。重启从节流扫描重建索引；未索引、被挤出或未收到通知的任务保留扫描恢复入口。前台活动和资源压力期间不启动索引任务。关闭服务会清空内存提示，不删除持久化待办。新增 `delayed`、`nextRetryAt`、`scansStarted` 状态观测字段。

## 回归验证

- 真实目录中混合未评价卡片、已完成且确认的记录、无关文件，共超过 4000 个目录项；保留默认 `scanPauseMs=100`，分别验证未开始扫描和扫描进行中的 503→200 原样重试。
- 前台覆盖重试到期时不发请求、无常驻上报 Worker、无调度计时器；结束后恢复。新撤销可在旧重试期限前上报，不重放旧赞。
- 重试索引满载 1024 项，第 1025 项仍保留 receipt；到期扫描恢复成功。已完成记录的旧内存提示会重新校验，不产生重复 HTTP。再次重启没有多余投递。
- 索引优先保留较早期限、返回被挤出项供扫描恢复；同一卡片连续更新一万次不增加索引大小。原有 128 条 pending 不阻塞新评价及重启退避回归继续通过。
- 全量结果：182 个测试文件、1933 项通过；行覆盖率 86.34%、分支覆盖率 81.22%。OpenClaw 2026.8.1、2026.9.34、2026.10.7 类型检查，格式、lint、运行时/声明构建、包检查和文档构建通过。Lint 为 86 条现有警告、零错误。

大目录回归只加快调度 tick 至 10ms，扫描间隔保持默认；索引满载测试为验证容量与持久化恢复而使用加速扫描和可控时钟。以下性能测量同时使用默认 tick 与默认扫描间隔，不能将回归测试的时间断言当成默认配置交付 SLA。

本轮普通重试没有随历史文件量线性增长；约 1 秒剩余等待包含默认调度与资源采样。五个样本均为两次请求、同一版本原样重试、最终终态 ACK，未因修复新增发送失败。

另一个一万文件样本覆盖前台跨过重试期限：前台期间不发送、无上报 Worker 或调度计时器；结束后约 7057 ms 完成补传，包含空闲和资源检查等待。该路径仍服从资源退让，不承诺前台结束后 1 秒内完成。六个样本的主线程定时器额外延迟 P99 约 2.39～2.49 ms。

对该等待另做一次对照：基线 80 文件样本前台结束后 11044 ms 完成，修复后一万文件样本为 7054 ms；两者均记录了原有的资源压力暂停和恢复事件。因此本次消除的是目录扫描附加等待，未修改资源退让判定。额外对照端口为 57319、57331，详细事件时间保存在原始结果中。

实际本机接收端口依次为 56988、56995、57012、57026、57031、57038；由操作系统分配空闲端口，测试结束关闭。原始脱敏结果：`docs/assets/feedback-retry-index-2026-10-26/results.json`。

复现入口（在源码开发环境运行，使用项目依赖）：

```bash
node scripts/build-feedback-benchmark.mjs .local/retry-benchmark
node .local/retry-benchmark/feedback-retry-benchmark.mjs \
  --history-files 10000 --output .local/retry-benchmark/result.json
```

加 `--startup-scan` 验证扫描并行，`--foreground` 验证前台退让。对照构建通过 `--service-module` 指定：该 bundle 必须同时导出 `FeedbackReportingService` 与 `applyFeedback`，使服务和评价入口共用事件总线。本次只将 service 源文件替换为固定基线，其他依赖及 Worker 相同。基准脚本不接触员工状态，不启动网关；状态、配置、缓存及 TMPDIR 仍应设置到独立目录。

## 真机与边界

修复已在保留的 OpenClaw 2026.10.7 临时网关热加载，18789 端口、钉钉 running/connected 正常。固定答案服务和 SQLite 事务接收端仍为 58183/58182。原提问者实际撤销旧卡片点赞，确认按钮恢复未选中；第 2 版 none 已入库，原问答保持 available 且对应正确问题。

随后重新开启受控 503 窗口，原提问者再次点赞并确认操作完成。2026-10-26 12:56:42（Asia/Shanghai）回调保存 like，12:56:43 首次请求收到 503 并持久化失败回执。观察器捕获失败后恢复接收端；无需重启或再次点击，12:56:50 第 3 版自动补传并获得终态 ACK，重试期限到确认约 1061 ms。失败时持久化请求的 SHA-256 与接收数据库提交的 request_hash 一致，数据库版本为 3、最新评价为 like、正文保持 available。接收端恢复为 200，全部故障注入开关关闭。客户端确认、失败回执、日志与 SQLite 入库结果已交叉核对。

重启首次发现和索引溢出仍依赖节流扫描，可能受历史目录大小影响；本次不承诺所有恢复路径恒定耗时。一万文件基准为本机单次样本，不能外推为所有负载下的性能保证。Linux cgroup 容器及公司 OceanBase 未增加新的实机验证。按用户要求，临时环境留待通知恢复。
