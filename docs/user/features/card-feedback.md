# AI 卡片评价：点赞点踩、统计与问答反查

回答完成后，原提问者可以点赞、点踩、选择原因，或者再次点击撤销。可查询本人评价统计；具备精确转录关联的记录，还能查看对应原问题和回答。这些操作不会调用模型、自动修改提示词、生成学习规则或重答。

本文适用于在社区版 3.9.0 基础上包含本改造的构建，要求 OpenClaw `2026.8.1` 及以上。代码尚未发布到上游 npm；部署时请核对实际构建内容。

## 使用方式

| 操作 | 结果 |
| --- | --- |
| 点击赞 | 将当前回答记为点赞 |
| 再点已选中的赞 | 撤销点赞，恢复未评价 |
| 点击踩 | 将当前回答记为点踩，可选择多个原因 |
| 提交原因 | 为当前点踩保存原因；关闭面板不会撤销点踩 |
| 再点已选中的踩 | 撤销点踩及当前原因统计 |
| 从赞切换为踩，或反向切换 | 替换当前评价，不会累计两票 |

私聊与群聊都只接受原提问者的评价。群内其他成员可以看到原生按钮，但点击不会计入统计，后台会私信说明原因。转发卡片同样校验原提问者。没有可信提问者关联的旧卡片、主动通知和未完成的回答，不接受评价。

在机器人私聊中查询本人统计：

```text
/feedback stats
/feedback stats 30d
```

默认最近 7 天，可指定 1～365 天。时间范围按回答创建时间计算；只统计仍在保留期内、正常完成的回答。评价率 = 当前点赞和点踩回答数 / 可评价回答数。撤销不计票；原因可多选，因此各原因数量之和可能超过点踩数。群聊中不会输出个人统计。

## 从一条评价查看原问题和回答

原提问者在机器人**私聊**中发送：

```text
/feedback detail card_实际卡片ID
```

将 `card_实际卡片ID` 整段替换为管理员提供的完整 ID：在 JSON/CSV 导出中字段叫 **`cardId`**，在原始记录文件中叫 **`outTrackId`**，两者值相同，保留 `card_` 前缀。当前卡片没有直接查看问答的按钮，统计命令也不列出卡片 ID。

例如管理员提供 `card_example_001`，就发送 `/feedback detail card_example_001`；这是占位示例，请替换为实际 ID。命令直接查询，不调用模型，不在群里展示问答；群里产生的回答也由原提问者到私聊查询。

插件现在会在回答正常完成时，顺带保存实际会话 `sessionId`、原问题 `userMessageId`、回答 `assistantMessageId`。查询依次定位到 Agent → 当时的会话 → 两条具体消息，并核对回答 SHA-256 指纹。即使同一会话里两次回答文字完全相同，也不会用较新的回答替代。

例如：同一会话先问“如何导出 PDF？”，后问“手机上怎么导出 PDF？”，两次恰好都回答“点击导出按钮”。两张卡片分别保存各自的问题和回答 ID；查第一张卡片，只返回第一个问题及其回答。

边界：

- 只对本次升级后、宿主提供足够消息事件且能够唯一匹配的回答保存精确关联；旧记录不会自动扫描补填。
- 原始转录仍由 OpenClaw 保存，基础评价记录不复制问答全文；可选 HTTP 上报开启后，会在后台读取被评价的一问一答，待发送文件可暂存正文并交由公司接收服务保存。转录被清理、归档后无法读取或发生变化时，会明确提示，不能靠指纹还原正文。
- 卡片文本与转录不完全一致、来源不明确或有多条候选时，仍保存评价，但不猜测问答归属。
- 查询前检查账号、原提问者和记录保留期。知道别人卡片 ID 也不能读取其问答。
- 详情在独立 Worker 中按上限读取，与 HTTP 上报是否开启无关。每次总读取量最多 8 MiB、单条事件最多 1 MiB、问答正文 JSON 最多 128 KiB，Worker 老生代预算 128 MiB，查询期限 10 秒。超出预算会明确暂缓，不把原转录判为损坏或删除。
- 每实例同一时间只接受一个详情读取；并发查询提示稍后重试。读取前等待后台上报 Worker 退出，避免两种读取争抢资源；超时或插件停止时终止详情 Worker。
- 详情最多展示原问题前 1000 字符、回答前 2500 字符，超出会提示截取；完整正文仍在原转录中。展示不含思考或工具调用块。

正常回复期间不扫描转录、不增加网络或模型调用，关联字段合并到已有记录写入；基础功能只有主动执行 `detail` 时读取相应转录；开启可选 HTTP 上报后，空闲 Worker 还会按精确引用读取被评价问答。

## 安装与启用

完整步骤见[部署与升级指引](../getting-started/card-feedback-deployment.md)，涵盖现有模板判断、安装包、OpenClaw 配置、服务环境、Kubernetes/PVC、容量规划和回滚。

首次启用不是只更新插件：需要包含本改造的运行时、`messageType: "card"` 与 `feedbackEnabled: true`，以及开启赞踩并回传 **`feedback_vote`** 的模板。已有可编辑的同类模板通常只需修改设置；无权限或不能编辑/更新时，导入新模板并切换实际模板 ID。

当前实现通过实际网关进程的 `DINGTALK_CARD_TEMPLATE_ID` 环境变量选择内置流式模板，不能只改 `channels.dingtalk.cardTemplateId`。平台模板不会随插件安装自动更新。验收必须使用开启功能后新建的正常回答卡片。

## 记录与导出

记录保存在钉钉账号 `storePath` 同级的 `dingtalk-state/feedback.ratings.*.json`。每张开启功能后的关联卡片一个文件，点击前就会保存归属；未完成/失败卡片也可能留下记录。文件保存原消息 ID、卡片 ID、提问者 UserId、会话和 Agent、回答内容哈希、可用时的转录消息 ID、当前评价和有限操作历史，不复制问答全文；可选上报的待发送正文位于另一组 outbox 文件中。

文件权限为 `0600`。最多保留最近 100 次状态变化和 256 个去重事件 ID；服务端时间早于已处理事件的旧回调不会覆盖新状态。记录可跨网关重启恢复，过期卡片不再接受评价。同一进程中，每个账号路径在新建记录时最多每 24 小时触发一次异步过期清理，统计查询也会清理过期记录。重启会重置清理触发间隔；没有新记录/查询或清理失败时，过期文件可能仍在磁盘。当前没有总文件数或总磁盘大小的硬配额。

管理员可以在有权读取对应 Pod 数据目录的终端导出：

```bash
node scripts/feedback-export.mjs \
  --state-dir /home/node/.openclaw/agents/default/sessions/dingtalk-state \
  --account default --days 30 --format json
```

路径仅为默认示例，应使用实际钉钉账号存储位置。可加 `--user '<UserId>'` 只导出某人的记录，或用 `--format csv` 输出 CSV。导出额外包含 `transcriptStatus`、`transcriptReason`、`sessionId`、`userMessageId`、`assistantMessageId`；旧记录状态为 `not-recorded`。命令只读取本地数据，不联网、不修改记录；访问控制沿用操作系统与 Pod 文件权限。

## 可选：集中上报评价与问答

需要将最新评价及对应一问一答集中入库时，可启用[通用 HTTP 上报](./feedback-http-reporting.md)。接收服务按协议写入公司数据库，插件不直连数据库；本地评价仍负责卡片交互。

## 存储容量与数据库

单条 JSON 内容通常较小，但文件系统分配块与集群文件数量需要一起计算。容量按“每日新建关联卡片数 × 保留天数”评估，不能只按点赞数量估算；容量估算方法见[部署指引的存储章节](../getting-started/card-feedback-deployment.md#_8-数据在哪里、占多少空间)。

插件不直连数据库。可选 HTTP 上报已提供最新评价及对应一问一答的同步协议，由公司接收服务入库；默认关闭，沿用当前卡片模板。开启后仍保留本地评价，并为已纳入同步的卡片增加有界待发送文件和回执。若数据库要替代本地 JSON 主存储，仍需开发存储适配层。JSON/CSV 导出是另一种离线快照，不能当作完整历史或无损迁移文件。

## 排查

- **按钮变色，后台没记录**：先检查 Action ID 是否仍为 `sys_action_like_component`；界面效果不能替代 Stream 回调证据。
- **按钮不保持选中**：检查是否收到 `feedback_vote`、是否启用功能、是否存在归属记录，以及回调响应是否包含 `userPrivateData`。
- **提示没有回答关联**：通常是旧卡片或主动消息；不会把它错误归到最近的一次回答。
- **提示尚未完成**：流式输出、模型登录失败或异常占位卡不应计作正常回答。
- **点击后没有确认消息**：成功评价不额外发送聊天消息；原生按钮状态即为反馈。拒绝提示会限频，避免刷屏。
- **保存失败**：日志会出现 `[DingTalk][Feedback] Persistence failed; callback not acknowledged`。检查磁盘、文件权限和损坏记录；此时不会回写成功选中状态，并保留平台重试机会。
- **重启后丢失**：确认 Pod 的状态目录持久化，且实例重启前后使用相同的账号存储路径。
- **显示“旧记录未保存消息 ID”**：该记录没有精确引用字段；升级不会自动扫描转录补填，应以升级后新回答验收。
- **记录是 `unavailable`**：宿主事件不足、来源或候选不明确、文本不完全一致等情况会保守放弃关联；评价和统计仍按原规则工作，管理员可查看 `transcriptReason`。
- **显示转录无法读取或校验不一致**：检查实际 Agent 的转录是否仍在、可读且未改动。评价保留期与宿主转录保留期分别管理，指纹无法恢复被删除的正文。
- **显示查询繁忙、超时或读取预算不足**：稍后重试；持续超限时由管理员检查转录大小与宿主资源。详情限制独立于 `feedbackReporting` 配置，不会为完成查询回退到主线程全量读取。
- **客户端详情正文暂时显示不全**：先切换到其他会话再返回，排除客户端消息高度未刷新；长文本被主动截取时会明确提示。DWS 查询的文本投影可能省略 Markdown 引用块，不应据此认定正文丢失。

该能力与 [`/learn` 反馈学习](./feedback-learning.md) 分开。开启 `feedbackEnabled` 不等于开启 `learningEnabled`，赞踩不会自动产生学习规则。
