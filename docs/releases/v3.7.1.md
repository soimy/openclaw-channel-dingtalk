# v3.7.1 发布说明

本次 patch 版本收口 ClawHub 安全审计在 [`Issue #616`](https://github.com/soimy/openclaw-channel-dingtalk/issues/616) 中记录的剩余项：把 host-callable 的 Gateway RPC 默认关闭、让 `learningEnabled` 成为学习回路的真正总开关、为学习规则加上有效期与账号级授权开关，并把 ClawHub beta 安全审计接入发版门禁。v3.7.0 本身即是为适配新版本 OpenClaw 而做的破坏性审计补丁，本次沿同一版本线以 patch 发布，破坏性默认值变更集中列在下方。

> [!IMPORTANT]
> 本版本包含**默认值收紧**，升级前请阅读「行为变更」章节：`gatewayCapabilities.tools.*` 默认由 `true` 改为 `false`；`learningEnabled` 关闭时不再允许写入学习规则、已存规则也不再生效；学习规则默认 30 天后过期；`/learn global` 默认被拒绝。

**最新版本入口**：[`latest.md`](./latest.md)

## ⚠️ 行为变更（默认值收紧）

### 1. Gateway RPC 能力默认关闭

* [`PR #617`](https://github.com/soimy/openclaw-channel-dingtalk/pull/617)（by @soimy）回应 ClawHub 审计对 `gateway-docs-and-send-rpc` 的 finding（[`Issue #608`](https://github.com/soimy/openclaw-channel-dingtalk/issues/608)）：`gatewayCapabilities.tools.docs` 与 `gatewayCapabilities.tools.proactiveSend` 的默认值由 `true` 改为 `false`。
  * 需要 docs / 主动发送 RPC 的部署请显式设为 `true`，并按需配置 `gatewayCapabilities.docs.allowedSpaceIds` 与 `gatewayCapabilities.send.allowedTargets`。
  * 拒绝信息会点名所需配置键（例如提示 `gatewayCapabilities.tools.docs defaults to false`），便于按提示恢复，不必翻源码。
  * `openclaw.plugin.json` 的默认值与运行时解析结果现已由测试绑定，避免声明与实现再次漂移。

### 2. `learningEnabled` 成为学习回路总开关

* `learningEnabled` 此前只控制学习内容注入 prompt；`/learn` 写命令与精确回复（`forcedReply`）不受它约束，导致「关闭开关」并不能真正停止学习回路。
* 现在关闭时：拒绝写入/修改类学习命令，**已存规则也不再命中**（消息回落到正常 agent 流程）；只读与清理命令（`/learn list`、`/learn disable`、`/learn delete` 等）保持可用，便于移除历史规则。
* 依赖学习规则生效的部署需显式设置 `learningEnabled: true`。

### 3. 学习规则的有效期与账号级授权

* 新增 `learningRuleTtlMs`（默认 30 天，设 `0` 关闭过期）：超期规则**既不会被注入 prompt，也不会命中触发语**，需要重新发布。
* 新增 `learningAllowManualGlobalRules`（默认 `false`）：owner 写入的 account 级规则默认整条链路关闭 —— `/learn global` 写入会被直接拒绝并给出会话级替代命令；历史 account 级规则也不注入、不强制回复。
  * 需要账号级规则时显式开启；若只是想让多个会话生效，使用 `/learn targets <id1,id2>` 或 `/learn target-set apply <名称>`，它们写的是会话级规则，无需该开关。
  * 自动学习产生的 account 级规则不受该开关约束，仍由 `learningAutoApply` 控制。

## 🔒 安全与审计

* **ClawHub beta 安全审计成为发版门禁**
  * 新增 `.github/workflows/clawhub-publish.yml`：`audit` 与 `publish` 拆成两个 job，审计通过后才进入发布；审计版本写入独立的 `audit` dist-tag，不污染 `latest` / `beta` 通道。
  * 门禁策略（P2）：`Malicious`、`blockedFromDownload`、`pending`、`stale` 等一律硬失败；`suspicious` 需显式 `ALLOW_SUSPICIOUS=1`（`workflow_dispatch` + `allow_suspicious=true`）并留下复核记录，tag push 不接受覆盖。
  * 门禁加固：CLI 固定到 `clawhub@0.23.3`（`0.23.1` 的 `package delete --version` 是永久删除，`--wait` 与可撤回语义自 `0.23.2` 起才有）；离线 `clawhub package validate` 移到鉴权之前；`trust` 字段做严格类型校验，畸形结论按硬失败处理。
  * 发布 job 绑定审计 job 输出的 `audited_commit`，并在发布前重新解析 tag 并用 `^{commit}` 复核 tag 未被移动，避免「审了 A、发了 B」。
  * 新增本地等价入口 `scripts/clawhub-audit-local.mjs`（支持 `--dry-run`、`--allow-suspicious`、`--withdraw`，证据落在 `.clawhub-audit/`），与 `scripts/clawhub-beta-gate.mjs` 共用同一套判定。
  * 文档更新：[`docs/contributor/npm-publish.md`](https://github.com/soimy/openclaw-channel-dingtalk/blob/main/docs/contributor/npm-publish.md) 新增门禁章节（触发方式、策略、dist-tag 取舍、证据与本地复现）。

* **学习回路的可观测性与一致性**
  * 精确回复命中时输出 `[DingTalk][Learning][ForcedReply] ruleId=… scope=… target=…`（不含回复正文），不再静默覆盖回复。
  * prompt 注入、强制回复与 `/learn list` 改为共用同一套判定（`resolveLearnedRulePolicy()` / `resolveLearnedRuleState()`），过期规则与未授权的 account 级规则在三处表现一致。
  * `/learn list` 显示实际生效状态：`enabled`、`enabled, not applied (learning disabled / expired / global rules disabled)`、`disabled`。

> [!NOTE]
> ClawHub 的 ClawScan 判定是概率性的：同一份发布产物曾出现 `clean` 与 `suspicious` 两种结论（详见 [`PR #617`](https://github.com/soimy/openclaw-channel-dingtalk/pull/617) 的多轮实测记录）。因此门禁按 tripwire 使用，单次 `clean` 不作为通行证。

## 📦 配置项速查

| 配置项 | 变化 | 默认值 |
| --- | --- | --- |
| `gatewayCapabilities.tools.docs` | `true` → `false` | `false` |
| `gatewayCapabilities.tools.proactiveSend` | `true` → `false` | `false` |
| `learningEnabled` | 语义变更：成为学习回路总开关 | `false` |
| `learningRuleTtlMs` | 新增 | `2592000000`（30 天，`0` 关闭） |
| `learningAllowManualGlobalRules` | 新增 | `false` |

新增字段已同步写入 `openclaw.plugin.json` 的渠道级与 named account 两处 schema，并附 WebUI hint；用户文档见 [`docs/user/features/feedback-learning.md`](https://github.com/soimy/openclaw-channel-dingtalk/blob/main/docs/user/features/feedback-learning.md) 与 [`docs/user/reference/security-policies.md`](https://github.com/soimy/openclaw-channel-dingtalk/blob/main/docs/user/reference/security-policies.md)。
